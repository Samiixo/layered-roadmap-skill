# roadmap-architect

**Скилл для Claude, который превращает спецификацию и россыпь идей в карту развития: слои × стадии → блоки → модули → задачи.**

Большой продукт обычно развивается «от задачи к задаче». Задачи разбросаны по системе, к сделанному приходится возвращаться, а прод обновляется кусками. Этот скилл наводит порядок: строит структуру, по которой двигаются **слой за слоем**, а релизят **блоками**, а не отдельными задачами.

> Claude skill that turns a product spec and scattered ideas into a layered, staged development roadmap (JSON + interactive HTML + Markdown). Works in Claude.ai and Claude Code. Russian-first, language follows the user.

## Идея: две оси, которые не смешиваются

| | Вопрос | Пример |
|---|---|---|
| **Слой** | На чём это стоит? | L0 стек, L1 авторизация, L2 ядро данных, L3 ключевые сценарии |
| **Стадия** | Когда и для кого выходит? | S1 MVP, S2 доступ для читателей, S3 монетизация |

Каждый **блок** лежит ровно в одной ячейке матрицы, имеет критерии готовности (DoD) и является **единицей релиза**. Если функция растёт, её делят на версии-блоки по стадиям («Поиск v1» в S1, «Поиск v2» в S3).

Новая функциональность вписывается в карту **целым блоком** в нужную ячейку. Задачи не раскидываются по карте, и всегда видно, готов ли блок полностью.

## Что делает скилл

1. Собирает все источники: спеку, репозиторий, заметки, идеи из разговора.
2. Выписывает плоский пул возможностей и отмечает, что уже существует.
3. Раскладывает по слоям с учётом зависимостей.
4. Группирует в блоки, модули и задачи.
5. Собирает MVP как тонкий вертикальный срез через нужные слои.
6. Проверяет карту валидатором.
7. Выдаёт три файла.

| Файл | Назначение |
|---|---|
| `roadmap.json` | Единственный источник правды |
| `roadmap.html` | Интерактивная карта: матрица слой × стадия, вид по слоям, фильтр по стадиям, отметки задач и DoD, экспорт JSON |
| `ROADMAP.md` | Та же карта для репозитория |

## Режимы

- **Построение:** с нуля по спецификации и идеям.
- **Расширение:** добавить новый блок в существующий `roadmap.json`, не пересоздавая карту.
- **Синхронизация:** «авторизация готова», «поиск в работе» → статусы обновлены, файлы пересобраны.

## Правила, которые скилл соблюдает

- Блок в `tested` или `released` только при всех закрытых задачах.
- В прод уходят блоки целиком и только после тестирования.
- Зависимость блока лежит в той же или более ранней стадии.
- Детализация растёт с приближением: задачи расписываются для горизонтов `now` и `next`, а для `later` достаточно DoD.
- Допущения не прячутся, а записываются в `meta.assumptions`.

## Установка

**Claude.ai:** скачайте `roadmap-architect.skill` из [Releases](../../releases) и загрузите в настройках в разделе со скиллами.

**Claude Code:** скопируйте папку `roadmap-architect` в каталог скиллов:

```bash
git clone https://github.com/<ваш-аккаунт>/roadmap-architect.git
cp -r roadmap-architect/roadmap-architect ~/.claude/skills/
```

## Использование

Напишите Claude, приложив спецификацию:

- «Построй план разработки по этой спеке, раздели на слои и стадии»
- «Разложи проект по слоям, первая стадия MVP, вторая доступ для читателей»
- «Впиши в карту новый блок: уведомления по email» (с приложенным `roadmap.json`)
- «Обнови статусы: авторизация протестирована, поиск в работе»

## Скрипты без Claude

Скрипты работают отдельно, нужен только Python 3.

```bash
# проверить карту
python scripts/validate_roadmap.py assets/roadmap.example.json

# собрать HTML и Markdown
python scripts/build_outputs.py assets/roadmap.example.json --out ./out
```

Валидатор ловит: битые ссылки на слои, стадии и зависимости; циклы; зависимости из будущих стадий; блоки без DoD; `tested` и `released` при незакрытых задачах; пустой MVP. Предупреждает, если в первой стадии больше половины блоков.

## Структура репозитория

```
roadmap-architect/
├── SKILL.md                     # инструкции для Claude
├── references/
│   ├── methodology.md           # библиотека слоёв, правила стадий, шаблоны DoD
│   └── schema.md                # формат roadmap.json
├── assets/
│   ├── template.html            # шаблон интерактивной карты
│   └── roadmap.example.json     # пример
└── scripts/
    ├── validate_roadmap.py
    └── build_outputs.py
```

## Адаптация

- Слои в `references/methodology.md` это отправная точка. Переименуйте их под свою предметную область.
- Названия и число стадий определяются вашими аудиториями и целями, а не шаблоном.
- Внешний вид карты меняется в `assets/template.html` (цвета заведены переменными CSS, есть тёмная тема).
