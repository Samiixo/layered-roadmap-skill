# Процессы: релиз, закрытие слоя, ритм сессии

## 1. Релиз блока

Единица релиза — модуль или блок. Задача сама по себе в прод не уходит.

Порядок:

1. Все модули блока на всех объявленных поверхностях в статусе «собран».
2. Пройден `dod` блока → модули «проверены».
3. Прогон `python3 scripts/build_roadmap.py docs/roadmap.json --check` — расхождений нет.
4. Релиз: миграции в git → сборка → деплой → health зелёный → ошибки видны в мониторинге → откат проверен.
5. Отметка: модули → `in_prod`, тег релиза `L{номер}-{slug-блока}`, запись в журнал проекта, `meta.updated`.
6. Пересборка доски: `python3 scripts/build_roadmap.py docs/roadmap.json`.

Код из незакрытого слоя не уезжает в прод попутно: фича-флаги по умолчанию выключены, включение — отдельное решение, зафиксированное в карте.

## 2. Закрытие слоя

Слой закрывается, когда **все его блоки в проде** (перенесённые не считаются) и выполнен `exit` слоя.

1. Пройди по `exit` слоя пункт за пунктом и проверь фактами, а не памятью.
2. Прогони валидатор: расхождения запрещены.
3. Релиз слоя: тег `L{номер}`, запись в журнал.
4. Ретроспектива на 10 минут: что перенеслось и почему; что оказалось лишним; не изменились ли критерии закрытия следующего слоя. Итог — правками в карту.
5. Объяви следующий слой. Только теперь он текущий.

**Перенос вместо закрытия.** Если блок не готов, а слой почти собран, есть два честных пути: перенести блок целиком в следующий слой (`deferTo`) или, если он не критичен для зрелости, отправить в резерв. Недопустимо оставлять блок «наполовину здесь, наполовину там».

## 3. Ритм сессии агента

**Вход (5 минут).**

```bash
python3 scripts/build_roadmap.py docs/roadmap.json --next
```

Печатает: текущий слой и критерий его закрытия, что уже в работе (это и доводим), следующий блок по зависимостям, что заблокировано и сколько позиций в резерве. Из вывода выбираются один блок и один–два модуля. Больше не берём.

**Работа.** Идти по модулю до конца. Если по ходу выяснилось, что нужно ещё что-то — это либо новый модуль в этом же блоке, либо запись в резерв, но не «заодно сделаю».

**Выход (10 минут).**

1. Обновить `docs/roadmap.json`: статус модуля, `evidence` с путями.
2. `python3 scripts/build_roadmap.py docs/roadmap.json --check` — расхождений нет.
3. `python3 scripts/build_roadmap.py docs/roadmap.json` — пересобрать доску и сводку.
4. Запись в журнал проекта: что сделано, что открыто, что отложено.
5. Коммит карты вместе с кодом — одним коммитом, чтобы статус и реальность менялись одновременно.

**Лимиты.** Один блок в работе на слой, максимум три модуля одновременно. Не начинать то, что не закрывается до конца рабочего дня: лучше зафиксировать текущее и остановиться на границе.

## 4. Гейт на коммите

Проверка расхождений ставится хуком, чтобы дисциплина не зависела от памяти. Готовый скрипт — `assets/templates/pre-commit`.

```bash
cp assets/templates/pre-commit .githooks/pre-commit
chmod +x .githooks/pre-commit
git config core.hooksPath .githooks
```

Хук срабатывает, только если в коммит попала карта, её сводка, доска или генератор. Обойти разово — `git commit --no-verify`, отключить — `git config --unset core.hooksPath`.

## 5. Работа с агентами

- **Один блок — один агент.** Параллелить можно только между блоками, не пересекающимися по файлам.
- **Контракт агента:** вернуть изменение статуса модуля, доказательства и код — или честное «не сделано, потому что». Без записи в карту работа не считается выполненной.
- **Разные роли — разные блоки.** Если над проектом работают несколько агентов (бэкенд, фронтенд, QA), они берут модули из одного блока, а не блоки из разных слоёв.

## 6. Резерв: когда разбирать

Резерв не разбирается по одной позиции. Триггеры для волны:

- закрыт очередной слой — посмотреть, не пора ли;
- накопилось больше ~30 позиций — значит, склад стал свалкой, надо переносить или удалять;
- появился свободный ресурс — взять резерв целиком, одной волной, и закрыть как обычный слой.

При разборе каждая позиция либо переезжает в слой (снимается `deferTo`), либо удаляется совсем. Оставлять «на всякий случай» нельзя: карта должна отражать намерения, а не архив фантазий.

## 7. Типичные ошибки и что делать

| Симптом | Причина | Что делать |
|---|---|---|
| Валидатор падает: «заявлен собран, модули дают в работе» | Блок объявили готовым при недоделанном модуле | Понизить статус блока или перенести модуль |
| Проценты слоя стоят на месте неделями | Работа идёт не по текущему слою | Вернуться к `--next` и брать только оттуда |
| В карте появились числа и формулы | Перепутали карту со спецификацией | Перенести в спеку блока, из карты убрать |
| Резерв растёт быстрее слоёв | Туда сваливают всё сомнительное | Разобрать волной: в слой или удалить |
| Агент начинает работу не из карты | Правило не прописано в агентском файле | Добавить правило и вставку из `agent-files.md` |
