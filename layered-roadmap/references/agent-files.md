# Что и куда писать: агентские файлы

Карта работает, только если агент про неё знает. Ниже — куда именно прописывать правило в зависимости от того, чем пользуется проект.

## 1. Куда писать

| Файл проекта | Кто его читает | Что добавить |
|---|---|---|
| `AGENTS.md` | большинство агентских сред (ZCode, Codex, Cursor, Cline) | правило «карта — источник правды о порядке» целиком |
| `CLAUDE.md` | Claude Code | то же правило, можно короче + ссылку на `docs/ROADMAP.md` |
| `.cursor/rules/*.mdc` | Cursor | короткое правило + ссылка на карту |
| `README.md` | человек и агент | раздел «Карта развития»: где лежат файлы и как пересобрать |
| `INDEX.md` / `docs/README.md` | навигация | строка каталога «порядок развития → файлы карты» |
| журнал проекта (`STATE-LOG.md`, `CHANGELOG.md`) | человек | запись о релизе блока и закрытии слоя |
| `.githooks/pre-commit` | git | гейт: валидатор перед коммитом |

Если в проекте нет ни `AGENTS.md`, ни `CLAUDE.md` — создай `AGENTS.md`, это самый нейтральный формат.

## 2. Правило для AGENTS.md

Готовая вставка лежит в `assets/templates/AGENTS-snippet.md`. Скопируй блок и подставь свои пути и идентификаторы. Кратко, о чём оно:

1. Где лежит карта и что она — источник правды о порядке работ.
2. Иерархия: слой → стадия → блок → модуль.
3. Единица релиза — модуль или блок.
4. Правило расширения: новая работа входит блоком или модулем, коммит без записи в карту считается незавершённым.
5. Правило горизонта: блок не закрывается наполовину, необязательное — в резерв.
6. Статусы и требование доказательств.
7. Две команды: `--next` на входе, сборка с `--check` на выходе.
8. Гейт на коммите.

Проверь, что правило стоит **до** длинных разделов про стек: агенты читают начало внимательнее.

## 3. Раздел для README.md

Вставка — `assets/templates/README-snippet.md`. Смысл: короткий раздел, из которого человек за 10 секунд понимает, где карта, как её открыть и как пересобрать.

Внутри должно быть:

- одна фраза про модель (слои закрываются по порядку, единица релиза — блок);
- ссылки на `docs/ROADMAP.md`, `docs/roadmap.json`, `ROADMAP.html`;
- команды: `--next`, `--check`, сборка;
- правило про то, что новая работа входит блоком.

## 4. Сообщение сессии

Если проект ведётся сессиями с агентом, добавь в открывающее сообщение блок-пометку (`assets/templates/session-opening.md`). Он делает три вещи: велит агенту начинать с `--next`, запрещает брать работу вне текущего слоя и требует обновить карту перед финалом.

Короткая версия одной строкой, если длинный блок неудобен:

```
Работаем по карте: начни с `--next`, бери только текущий слой,
в конце обнови docs/roadmap.json и прогони сборку с проверкой.
```

## 5. Журнал проекта

На релиз блока и закрытие слоя — запись в журнал проекта (тот, что уже есть: `STATE-LOG.md`, `CHANGELOG.md`, `docs/journal.md`). Формат записи:

```
## {дата} — релиз L{N}.{M} «{название блока}»
Что вошло: перечень модулей.
Доказательства: тег, миграции, ссылки на тесты.
Открыто / перенесено: что и куда.
```

Журнал отвечает на вопрос «что уже случилось», карта — «что и в каком порядке». Не смешивай их: журнал дополняется, карта переписывается.

## 6. Порядок внедрения карты в чужой проект

Когда карту строят для проекта, где уже есть документация:

1. Найди в проекте противоречащие планы (роадмапы, дорожные карты, планы по вехам). Если их несколько — предложи оставить один, остальным поставить в шапку пометку «архив, заменён картой».
2. Пропиши правило в агентском файле и добавь пункт в раздел «поддержание порядка»: менялся статус — правка карты в том же коммите.
3. Поставь хук. Он дешевле любых договорённостей.
4. Исправь числа в документации, которые разошлись с кодом: их находишь при инвентаризации, и они лучший аргумент, что карта нужна. Только факты из кода, без предположений.
5. Проверь, что `--next` печатает осмысленный ответ на пустой карте и на большой: иначе правило не приживётся.

## 7. Что писать не нужно

- Не дублируй содержимое карты в `README`: ссылки достаточно.
- Не заводи второй трекер (доску, таблицу, файл задач) параллельно карте.
- Не описывай в агентском файле процесс целиком — там место правилу и ссылке на `docs/ROADMAP.md`.
- Не превращай журнал в план: план живёт в карте.
