# Модель карты

Полная модель: сущности, статусы, свёртка, горизонты, резерв.

## 1. Иерархия

```
Слой (уровень)   →   Стадия (группа слоёв)
Блок             →   Модуль   →   Задача
```

| Сущность | Что это | Обязательные поля |
|---|---|---|
| **Слой** | Ступень зрелости. Закрывается целиком, только после этого начинается следующий | `id`, `name`, `goal`, `dependsOn`, `exit`, `blocks` |
| **Стадия** | Группа слоёв. Отвечает на вопрос «что за продукт получается» | `id`, `name`, `levels`, `product`, `can`, `audience`, `missing` |
| **Блок** | Поставляемая целиком единица. Единица релиза | `id`, `name`, `why`, `surfaces`, `dependsOn`, `status`, `horizon`, `dod`, `evidence`, `modules` |
| **Модуль** | Часть блока. Определяет статус блока | `id`, `name`, `what`, `surface`, `status`, `evidence` |
| **Задача** | Единица коммита. Живёт в коде, ссылается на модуль | — |

**Задачи не определяют статус.** Статус выводится из модулей, статус слоя — из блоков. Иначе карта превращается в список дел и перестаёт отвечать на вопрос «готов ли блок целиком».

### Поверхности

У блока объявлен набор целевых поверхностей: `web`, `mobile`, `admin`, `api`, `backend`, `etl` — что угодно, список задаётся в `meta.surfaces`. Блок не может быть собран, пока не реализован на всех объявленных поверхностях. Так паритет платформ становится свойством каждого блока, а не отдельной вехой «когда-нибудь потом».

```json
"meta": { "surfaces": { "web": "веб", "mobile": "мобильное", "api": "API", "admin": "админка" } }
```

Если `meta.surfaces` не задан, используются ключи как подписи.

## 2. Статусы

```
не начат  →  в работе  →  собран  →  проверен  →  в проде
```

Два исключительных состояния:

- **на паузе** — работа невозможна; обязательное поле `blockedBy` с причиной.
- **перенесён** — блок или модуль уходит из слоя; обязательны `deferTo` (в какой слой) и `deferReason`. Перенесённое не участвует в свёртке и видно отдельным списком.

Ключи в JSON: `not_started`, `in_progress`, `assembled`, `verified`, `in_prod`, `paused`. У слоя-резерва статус выводится как `reserve`.

### Что требуется для перехода

| Переход | Доказательство |
|---|---|
| → **в работе** | есть коммит, затрагивающий модуль |
| → **собран** | все модули реализованы на всех объявленных поверхностях; типы и сборка проходят |
| → **проверен** | выполнен `dod` блока: тесты, ручная проверка по чек-листу, адаптив и доступность, миграции закоммичены, документация обновлена, фича-флаг заведён |
| → **в проде** | задеплоено, health-проба зелёная, ошибки видны в мониторинге, есть запись в журнале с тегом релиза |

`evidence` — не украшение: пути к файлам, миграциям, тестам, ссылки на коммиты и записи журнала. Валидатор предупреждает, если у модуля со статусом выше «не начат» нет доказательств.

## 3. Свёртка

- **Статус блока** = худший статус среди его модулей, перенесённые не учитываются.
- Блок с одним «не начат» не может быть «собран».
- **Пауза внутри блока** опускает статус всего блока до «на паузе» — но пауза блока не опускает слой: приостановлен блок, а не стадия.
- **Статус слоя** = худший статус его блоков, перенесённые и блоки резерва не учитываются.
- **Текущий слой** = нижний незакрытый слой, не считая резерва. Он всегда один и он же ответ на вопрос «что делаем сейчас».

Валидатор считает эти статусы сам и падает, если заявленный в JSON статус расходится с расчётным. Это защищает от главной болезни карты: «почти готово» на бумаге при недоделанном модуле.

## 4. Горизонты

| Горизонт | Ключ | Смысл |
|---|---|---|
| В этом слое | `in_scope` | работа входит в закрытие слоя |
| Перенесён | `deferred` + `deferTo` | блок или модуль уехал в другой слой, причина в `deferReason` |
| За горизонтом | `beyond` + `deferReason` | не планируется, но зафиксировано |
| Резерв | `deferred` + `deferTo: "<id слоя-резерва>"` | полезное, но не критичное |

Перенесённое **не влияет на закрытие слоя**: именно это позволяет закрывать слои целиком, не откладывая релиз из-за одной недоделанной мелочи.

**Параметры не в карте.** Формулы, пороги, веса и константы живут в спецификации блока или в конфиге. Карта хранит то, что поставляется и закрывается.

## 5. Резерв

Последний слой-накопитель, помеченный `"reserve": true`. Сюда уходит всё, что признано полезным, но не критичным для зрелости продукта: редкие интеграции, узкие механики, идеи из ресёрча, улучшения «на потом».

- **Ничего не блокирует.** Ни один слой и ни одна стадия не зависят от резерва; текущим слоем он не бывает никогда.
- **Попадание:** `horizon: "deferred"`, `deferTo: "<резерв>"`, причина в `deferReason`.
- **Изъятие:** резерв собирается **разом, одной волной**, когда владелец решит. Отдельные позиции не выдёргиваются по одной — иначе резерв превращается в тот же поток задач, от которого уходили.
- **Статус** слоя-резерва — `reserve`: он не бывает «собран» или «проверен», критериев закрытия у него нет.
- **Волна резерва** не двигает статусы слоёв и не меняет текущий слой.

## 6. Слои и стадии

**Слои** упорядочены по зависимостям и закрываются последовательно.

**Стадии** — группы слоёв, отвечающие на вопрос «что за продукт на выходе»:

```json
"stages": [
  { "id": "S1", "name": "Работающий продукт", "levels": ["L0","L1","L2"],
    "product": "Что это за продукт после этой ступени",
    "can": "что уже умеет", "audience": "кому полезно",
    "missing": "чего ещё нет", "exitMeaning": "смысл ступени" }
]
```

Стадия закрыта, когда все её слои в проде. Стадии не планируются отдельно: они читаются из слоёв.

## 7. Что запрещено

1. Заводить второй источник правды (доску, файл задач, таблицу) параллельно карте.
2. Ставить статус без доказательств.
3. Закрывать блок с неначатым модулем — только переносить модуль или блок.
4. Переименовывать `id` существующих сущностей.
5. Класть в карту параметры и константы.
6. Тащить в текущий слой работу из будущего слоя «попутно».
