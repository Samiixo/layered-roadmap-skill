## Карта развития — источник правды о порядке работ

Порядок задаёт карта в репозитории: `docs/roadmap.json` (данные), `docs/ROADMAP.md` (правила и сводка),
`ROADMAP.html` (доска для человека). Иерархия: **Слой → Стадия → Блок → Модуль → Задача**.

- **Слой** закрывается целиком, только после этого начинается следующий. Текущий слой = нижний незакрытый.
- **Единица релиза — модуль или блок, никогда не задача.**
- **Правило расширения:** новая работа входит блоком или модулем в `docs/roadmap.json`. Коммит, добавляющий
  функциональность без записи в карту, считается незавершённым — наравне с коммитом без тестов.
- **Правило горизонта:** блок не закрывается наполовину. Не успевает — переносится целиком
  (`horizon: "deferred"`, `deferTo`, `deferReason`) с пересмотром зависимостей; модуль внутри блока может быть
  перенесён отдельно. Полезное, но не критичное для зрелости, уходит в слой-резерв (`deferTo` на слой с `reserve: true`).
- **Статусы:** `не начат → в работе → собран → проверен → в проде`, плюс `на паузе` (обязательно `blockedBy`).
  Статус блока = худший статус его модулей; статус слоя = худший статус его блоков. Каждый переход требует
  доказательства в поле `evidence` (пути к файлам, миграции, тесты, тег релиза, запись в журнале).
- **Параметры** (формулы, пороги, константы) живут в спецификации блока, а не в карте.

Команды:

```bash
python3 scripts/build_roadmap.py docs/roadmap.json --next    # что делать: текущий слой, что в работе, следующий блок
python3 scripts/build_roadmap.py docs/roadmap.json --check   # проверка расхождений, без записи
python3 scripts/build_roadmap.py docs/roadmap.json           # пересобрать доску и сводку
```

**Вход в сессию:** начни с `--next`, работай только с модулями текущего слоя.
**Выход из сессии:** обнови статусы и `evidence` в `docs/roadmap.json` → `--check` → сборка → запись в журнал →
коммит карты вместе с кодом.

**Гейт:** `core.hooksPath=.githooks`, хук прогоняет `--check`, если в коммит попала карта. Обойти разово —
`git commit --no-verify`.

### Обновление карты и документации

1. Менялся статус блока или модуля — правка `docs/roadmap.json` в этом же коммите.
2. Появилась новая функциональность — новый блок или модуль по правилу расширения.
3. Файл создан, удалён или переименован — строка в каталоге документации (`INDEX.md`) в этом же коммите.
4. Код важнее документов: расхождение трактуется в пользу кода, документы чинятся сразу.
