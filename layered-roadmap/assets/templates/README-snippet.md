# Вставки для README.md, каталога и сообщения сессии

## 1. Раздел README

Помещается между описанием стека и быстрым стартом. Подставь свои пути.

```markdown
## Карта развития

Порядок работ задаёт послойная карта: **Слой → Стадия → Блок → Модуль**. Слой закрывается целиком, и только
после этого начинается следующий; единица релиза — модуль или блок, а не отдельная задача.

- [docs/ROADMAP.md](docs/ROADMAP.md) — правила карты: статусы, условия переходов, правило расширения и релизов
- [docs/roadmap.json](docs/roadmap.json) — источник правды: слои, стадии, блоки, модули, зависимости, доказательства
- [ROADMAP.html](ROADMAP.html) — доска с прогрессом слоёв и фильтрами (открывается браузером)

```bash
python3 scripts/build_roadmap.py docs/roadmap.json --next    # что делать дальше
python3 scripts/build_roadmap.py docs/roadmap.json --check   # проверка карты
python3 scripts/build_roadmap.py docs/roadmap.json           # пересобрать доску и сводку
```

Скрипт работает и валидатором: если блок заявлен «собран», а один из его модулей «не начат», проверка падает
с объяснением. Новая функциональность входит в карту блоком или модулем; правка кода без записи в карту
считается незавершённой работой.
```

## 2. Строка в каталог документации

Если в проекте есть `INDEX.md`, `docs/README.md` или подобный каталог «вопрос → файл», добавь строку:

```markdown
| **Порядок развития: слои, стадии, блоки, статусы** | [docs/ROADMAP.md](docs/ROADMAP.md) + `docs/roadmap.json` + [ROADMAP.html](ROADMAP.html) |
```

## 3. Сообщение сессии для агента

Если проект ведётся сессиями, добавь в открывающее сообщение блок-пометку:

```
📐 Карта развития — рабочий контур сессии

1. Начни с `python3 scripts/build_roadmap.py docs/roadmap.json --next`.
   Это покажет текущий слой, что уже в работе, следующий блок и что заблокировано.
   Короткое резюме в начале сессии строй вокруг него.

2. Работаем только с модулями текущего слоя. Всё новое входит блоком или модулем
   в docs/roadmap.json, а не «заодно по пути». Полезное, но не критичное для
   зрелости — в резерв, а не в работу.

3. Перед финалом смены: обнови статусы и evidence в docs/roadmap.json →
   проверка → сборка доски и сводки → запись в журнал проекта → коммит карты
   вместе с кодом. При расхождении коммит не пройдёт: стоит гейт.

Доска — ROADMAP.html, правила — docs/ROADMAP.md.
```

Короткая версия одной строкой для быстрых промптов:

```
Работаем по карте: начни с `--next`, бери только текущий слой,
в конце обнови docs/roadmap.json и прогони сборку с проверкой.
```

## 4. Хук на коммит

Файл `pre-commit` из этой папки. Установка:

```bash
mkdir -p .githooks
cp assets/templates/pre-commit .githooks/pre-commit
chmod +x .githooks/pre-commit
git config core.hooksPath .githooks
```

Проверить, что всё работает: закоммить любое изменение `docs/roadmap.json` — хук прогонит валидатор.
Отключить: `git config --unset core.hooksPath`.

## 5. Запись в журнал проекта

Формат записи на релиз блока и закрытие слоя:

```markdown
## {дата} — релиз L{N}.{M} «{название блока}»

Что вошло: перечень модулей.
Доказательства: тег, миграции, ссылки на тесты и деплой.
Открыто / перенесено: что и куда, с причиной.

## {дата} — слой L{N} закрыт

Критерий закрытия: пройден по пунктам (список из карты).
Что оказалось лишним: …
Перенесено в следующий слой: …
```
